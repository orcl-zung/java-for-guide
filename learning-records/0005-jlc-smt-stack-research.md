## 六、锚点回填（2026-08-30 学员亲答，8/8 命中）

1. **解析**：SMT 部门做的（工程侧可能也有，需比对）。客户上传 BOM + 坐标文件 → 发起**两个解析任务** → 解析完成**上传到 ES** → 下单后有**匹配页**（矫正元器件贴片位置 + 采购元器件）→ 调整后下单 → **ERP 后台审核** → 工厂生产。（修正第二节推论：解析由 SMT 部门完成，"C++ 侧专属"不成立——简历口径就是"参与双解析任务链路迭代"）
2. **MQ**：解析产物经 MQ 对接；MQ 是公共组组件——**每个微服务三张表：消息 / 异常 / 失败**。定性：本地消息表（Transactional Outbox）的平台化封装；与 RocketMQ 事务消息、Outbox+CDC 的三方对比已写成完整应答脚本（reference/0002 项目二），并列为 W3 MQ 课必讲专题
3. **边界**：SMT 业务线 = 表面贴装；PCB 部门管 PCB 订单，板子生产完到 SMT 下单贴片 + 元器件采购；下单/报价/工单/状态回传主链路**早已建好**，学员做**迭代**——简历定位"成熟链路迭代"，防倒挂
4. **MQ = RabbitMQ**；5. **缓存 = Redis**（非 Memcached）
6. **量级**：订单"万级"（公开数据吻合，见下）；BOM 行更多（推导：日万级订单 × 每单数十行 = 日增数十万行、年累计亿级）
7. **计费**：按客户下单勾选的选项 + 配置计费——单/双面（PCB 顶底两面）、**按坐标点计费**、特殊工艺另计
8. **OSS**：文件存储需求极大；做过 **NAS → 云 OSS 迁移**（阿里云或腾讯云，学员记不清厂商；公开无 JLC 云厂商实锤 → 简历写"云对象存储"不写厂商；注意 OSS 是阿里云命名、腾讯叫 COS）；"API 级"= 基于厂商 API 对客户上传文件完全自主管理。与 Ingoo 阿里云 OSS + MinIO 形成跨公司连续性叙事

**量级公开数字（2026-08-30 检索，招股书/报道口径）**：集团 2025 年处理订单 **2129.08 万笔**（+19.56%，≈ 日均 5-6 万单）；注册用户 **959.16 万**（+34.73%）、付费用户 **130 万+**；立创商城现货 SKU 70 万+、年出货订单 390 万+；**PCBA（SMT）收入 17.89 亿（+49.68%，增速最快板块）**；官方口径智能拼板"日均可完成数万份订单组合、最快 12 小时出货"。集团总营收 102.32 亿、净利 13.06 亿。

## 八、二次锚点补强（2026-08-30 晚）

- **OSS 迁移角色定稿"参与"**（学员确认）
- **索引优化确认在 SMT 做过**（场景遗忘）→ reference/0002 建 4 场景认领清单：A 订单列表联合索引顺序 (status, create_time) / B BOM 明细 (order_id, line_no) + 覆盖索引 / C 隐式转换与函数包裹失效 / D 导出深分页——认领制，默认 A；口径"手法真实、数字不编"
- **财务对账（新王牌素材）**：SMT 订单对接财务需两边数据对平。两代真实方案：①数据库层 binlog 订阅对账 → ②API 对接 + MQ 重试。学员自评"治标不治本"——教练确认直觉正确：两代都停在**同步层**，重试防投递失败，防不了消息彻底丢 / 消费处理错 / 两边规则不一致（舍入分摊）/ 切日灰区。更优方案（已检索佐证：美团配送资金安全对账体系 = 在线对账 + 离线对账 + 平账中心；有赞业务对账平台、阿里商旅账单同构）：**三层对账体系** = 可靠同步（at-least-once + 幂等）→ 独立核对（准实时逐笔 + T+1 全量、总账先行控制爆炸半径，核对独立于同步链路）→ 差错池分级闭环（单边/金额/状态/灰区，自动重放冲正 + 人工工单，滚动窗口重跑 T-1/T-2）。已入简历第 4 条（"沉淀三层对账体系方法论"诚实措辞）+ 应答手册 ★★★ 对账题。面试弧线：亲历两代 → 反思出体系 → 出海项目落地核对层一半（分钟级主动对账 job）。
